# Океанические слои в проектах

В версии 0.8.0 лимит файла проекта составляет 200 МиБ в браузерном загрузчике, ядре редактора и нативных диалогах. Он учитывает сезонные карты океана: подробная сетка с высокой плотностью ресурсов может превышать прежние 100 МиБ. Правила по-прежнему ограничены 100 КБ.

Проект сохраняет годовой слой `climate.ocean` и четыре сезонных слоя. Каждый слой содержит метаданные `enabled` и `modelVersion`, а также типизированные числовые карты течений, температуры, аномалии и влияния на воздух. При загрузке карты восстанавливаются как `Float64Array`, после чего проверяются размер сетки, конечность значений, маска суши, скорость и годовые средние сезонов.

В 0.9 каждый кадр дополнен `thermodynamicsEnabled`, `thermodynamicsModelVersion: "two-layer-thermohaline-1"` и двухслойными картами солёности, плотности, глубинной температуры, глубинных течений и вертикального обмена. Все эти карты имеют тип `Float64Array`, кроме `deepMask`, которая имеет тип `Uint8Array` и одинакова для годового слоя и всех сезонов. Поверхностные карты 0.8 остаются в прежнем формате.

Проект без `climate.ocean` считается старым только когда в сохранённых активных правилах также нет раздела `generationRules.ocean`. Редактор сохраняет уже рассчитанные климатические карты и создаёт отключённый активный слой океана. Активные правила и правила атласа получают `ocean.enabled: false`; ожидающие правила редактора получают современное значение по умолчанию `true` для следующей генерации.

Если в проекте уже есть раздел `generationRules.ocean`, отсутствие самого климатического слоя считается повреждением данных и загрузка отклоняется. Такой проект нельзя молча заменить отключённой моделью.

Проект 0.8 с сохранённым поверхностным океаном мигрируется только при отсутствии одновременно активного `ocean.thermodynamicsEnabled` и метаданных термодинамики в годовом океаническом кадре. Его поверхностные карты остаются без изменений, активные правила мира и атласа получают `thermodynamicsEnabled: false`, а ожидающие правила редактора включают его для следующей генерации. Если хотя бы один признак новой модели сохранён, отсутствующие или некорректные глубинные данные считаются повреждением проекта.

Для следующей генерации можно импортировать [шаблон термохалинных правил](../examples/thermohaline-rules-example.json); он не изменяет уже сохранённые океанические карты.
