# Формулы генерации

Формулы позволяют заменить отдельные расчёты генератора, сохранив остальную цепочку мира. Это ограниченный числовой язык, а не JavaScript: в нём нет доступа к объектам, свойствам, строкам, массивам, `eval`, `Function` или внешнему состоянию. Пустая формула удаляется при сохранении и оставляет стандартный расчёт без изменений.

## Файл правил

Формулы сохраняются вместе с обычными правилами генерации. Экспорт использует оболочку версии 2, а импорт продолжает принимать оболочку версии 1:

```json
{
  "format": "worldgen-generation-rules",
  "version": 2,
  "rules": {
    "formulas": {
      "version": 1,
      "expressions": {
        "climate.temperature": "base + 2"
      }
    }
  }
}
```

Полный импортируемый пример находится в [`examples/formulas-example.json`](../../examples/formulas-example.json). В документе `formulas.version` должна быть `1`; ключи `expressions` — только известные точки расчёта.

## Язык выражений

Доступны числа, скобки, константы `pi` и `e`, арифметика `+ - * / % ^`, сравнения `< <= > >= == !=`, логические операции `! && ||`, тернарный оператор `условие ? да : нет` и ленивый `if(условие, да, нет)`.

Числовые функции: `sin`, `cos`, `tan`, `abs`, `min`, `max`, `clamp`, `sqrt`, `pow`, `exp`, `log`, `log10`, `floor`, `ceil`, `round`, `sign`, `lerp`, `smoothstep`. `rand([salt])` и `noise(x, y, z[, scale])` детерминированы seed мира и точкой расчёта. У `noise` координаты ограничены по модулю `1 000 000`, а `scale` должен быть положительным и не больше `1024`.

Результат каждого вызова обязан быть конечным числом и попадать в диапазон конкретной точки. Нельзя обойти положительные ограничения на массу, глубину и содержание: масса остаётся не меньше `1e-9` млн т, глубина — от `0.01` до `12 000` м, содержание — положительно и не выше единиц выбранного ресурса. Для `climate.runoff` верхняя граница дополнительно равна `precipitationMm`, а для `resources.grade` — `gradeDenominator`. Целочисленная точка `climate.biome` принимает только ID `1…8`.

## Общие переменные

Каждой формуле доступны числовые `base` (обычный результат), `latitudeDeg`, `longitudeDeg`, `elevationM`, `isOcean` (`1` или `0`), `season` (`0…3`, годовой расчёт `-1`) и координаты единичной сферы `x`, `y`, `z`. Редактор формы показывает дополнительно доступные переменные с единицами прямо для выбранной точки.

## Когда выполняются точки

`tectonics.elevation` применяется до подбора уровня моря по площади. В каждом из четырёх сезонов океан сначала получает ветровой дрейф (`ocean.east`, `ocean.north`), согласует поток, переносит тепло и вычисляет SST (`ocean.temperature`); затем `ocean.coupling` передаёт ограниченную береговую поправку воздуху. Базовое значение `climate.temperature` уже включает эту поправку. Конденсация идёт на каждом шаге переноса влаги. Испарение, сток и биом вычисляются для годового слоя суши; `erosion.incision` — на каждом проходе эрозии. `region.elevation` применяется только при открытии региональной детализации.

Поверхностная модель океана ограничивает скорость правилами `ocean.maxCurrentMps`, SST — `ocean.minSstC` и `ocean.maxSstC`, а температурную связь с воздухом — `ocean.maxAirCorrectionC`. Формулы не отменяют эти физические границы и вызываются только в океанских ячейках либо, для `ocean.coupling`, в области берегового влияния.

В 0.9 доступны 37 формульных точек, включая восемь новых термодинамических. `ocean.salinity`, `ocean.deepTemperature` и `ocean.deepSalinity` задают начальные трассеры до переноса. Формулы плотности выполняются до расчёта циркуляции и повторно на итоговых полях. `ocean.vertical` выполняется до балансировки подъёма и погружения по бассейну; `ocean.deepEast` и `ocean.deepNorth` — до проекции горизонтального потока. Итоговая скорость может отличаться от формулы из-за непрерывности и физических ограничений. При отключённой термодинамике эти восемь точек не выполняются.

Термодинамическим точкам доступны `freshwaterFluxMm`, `waterDepthM`, `seaTemperatureC`, `salinityPsu`, `densityKgM3`, `deepTemperatureC`, `deepSalinityPsu`, `deepDensityKgM3`, `deepEastMps`, `deepNorthMps`, `deepSpeedMps`, `verticalVelocityMps`, `deepMask`, `densityContrastKgM3`, ветер и исходная температура. Единицы показаны в редакторе. Ещё не рассчитанные поля на ранних стадиях равны нулю; `base` содержит результат именно текущей стадии. Пример: `clamp(base + 0.2, 0, 50)` для солёности или `base * 0.8` для вертикального обмена.

Предварительный сезонный климат и речная маршрутизация задают пресноводное воздействие до океана; окончательные осадки используют связанную SST. Поэтому при включённой термодинамике формулы конденсации выполняются в двух атмосферных проходах, а испарения/стока — в предварительном сезонном и итоговом годовом расчёте. Подробный порядок и приближения описаны в [термохалинной модели](ocean-thermodynamics.md).

После климата формулы геологии и почв строят осадки, почвы, опасности и среды рудообразования. `mineralization.formation` влияет на потенциал и пригодность тел. Формулы ресурсов влияют на число кандидатов, параметры тел и доступность; ограничение суммарного содержания компонентов тела сохраняется.

`resources.intensity` считается до выбора точек; его общие сферические координаты и координаты формулы равны нулю, поэтому эта формула задаёт количество кандидатов, а не пространственное поле. `mineralization.formation` не обходит сушу и порог среды модели: для океана или среды ниже `threshold` пригодность остаётся нулевой ещё до вызова формулы.

Проверка правил до генерации суммирует стоимость выражений и отклоняет расчёт свыше 300 млн условных операций. Во время размещения остаются два предохранителя: предрасчёт не принимает более 2 млн кандидатов, а цикл ограничен 2,1 млн попыток размещения. Ошибочный результат указывает формулу и ячейку/среду, после чего новый мир не фиксируется.

## Работа в редакторе

Во вкладке «Формулы» доступны проверка, таблица переменных, сброс и предпросмотр. Предпросмотр строит отдельный расчёт 48×24 ячеек не более чем на шести эпохах и не изменяет открытый мир.

Сохранение формулы меняет ожидающие правила редактора. Открытый мир и его активные формулы остаются прежними до новой генерации. Это относится и к кисти осадков: она пересчитывает сток и биом по активной формуле мира, а не по ожидающей формуле. Проект сохраняет оба набора правил, поэтому после загрузки можно продолжить настройку без подмены уже созданного мира.

Ручное добавление тела использует активные формулы `resources.mass`, `resources.depth`, `resources.grade` и `resources.access`. Его стандартные значения по-прежнему берутся из нижних границ модели; в формуле им соответствуют `minValue` и `sample = 0`. Проверка глубины, массы, содержания и суммарной доли компонентов выполняется и для такого тела.

Локальная перегенерация ресурсов может использовать другой seed размещения, меняя кандидаты залежей. Она сохраняет исходный seed геологической истории из атласа: рудные пояса, среды и карта потенциала не меняются из-за одного лишь нового seed размещения.
